Three complementary IaC layers coexist under `infra/`:
- `terraform/`: Root `main.tf` orchestrates modular AWS resources — VPC, security groups, RDS PostgreSQL, ElastiCache Redis, S3+CloudFront storage, ECS+Fargate with ALB, optional EKS cluster, Prometheus/Grafana monitoring, OpenSearch logging, and a secrets module that provisions AWS Secrets Manager entries plus optional HashiCorp Vault integration. Each capability lives in `modules/<name>/` with a uniform `main.tf` + `variables.tf` + `outputs.tf` contract, and is conditionally enabled via `count = var.enable_*` flags.
- `kubernetes/`: A Kustomize overlay (`kustomization.yaml`) composes base namespace/configmap/secrets, security policies, networking (Ingress, NetworkPolicy, Vertical Pod Autoscaler), and per-app manifests under `apps/` (backend Django, frontend Next.js, Celery worker, database). Images, replicas, and environment are patched at build time; Prometheus scrape annotations are baked into pod specs.
- `helm/jol-hub/`: A Helm v2 application chart (`Chart.yaml`, `values.yaml`) templating the same workload surface (backend, frontend, celery, postgresql, redis, ingress, networkpolicy, servicemonitor) for clusters managed by Helm rather than Kustomize.
Dependency direction: Terraform provisions the cloud control plane; Kubernetes/Helm deploy the app onto either an EKS cluster provisioned by Terraform or an external cluster. The two deployment targets share identical resource names and labels so manifests can be swapped without code changes.
