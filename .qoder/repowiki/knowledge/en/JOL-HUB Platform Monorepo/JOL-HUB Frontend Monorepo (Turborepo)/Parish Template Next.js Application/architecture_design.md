Built on the Next.js App Router under `src/app/`, the app is organized into three layers. The root layout (`src/app/layout.tsx`) provides global CSS and error boundaries; a locale-aware layout at `src/app/[locale]/layout.tsx` wraps every route in an `I18nProvider` from `@jol-hub/i18n/client`, sets `<html lang>`/`dir`, renders a sticky header with a `LanguageSwitcher`, and reads the tenant subdomain via the `x-subdomain` header injected by the edge middleware. The edge middleware (`src/middleware.ts`) runs before any page: it skips static/API paths, detects the active locale from URL path → cookie → Accept-Language → default (`lt`), redirects un-prefixed URLs to the resolved locale, sets a persistent `jol-hub-locale` cookie scoped to `.jol-hub.eu` in production, and injects `x-subdomain`, `x-parish-locale`, and security headers for downstream pages. Three template routes live under `src/app/templates/{parish,funeral,cemetery}/page.tsx`, each composing server-side data fetching (with ISR via `revalidate` or `next: { revalidate }`) and client-side feature components colocated in per-template `_components/` folders. A shared configuration module (`src/lib/parish-config.ts`) defines the `ParishConfig` shape and placeholder fetchers keyed by subdomain or ID, intended to be wired to Bitrix24/CMS backends. The app depends on workspace packages `@jol-hub/ui`, `@jol-hub/i18n`, `@jol-hub/auth`, and `@jol-hub/bitrix-sdk`, which are transpiled via `transpilePackages` in `next.config.js`.
