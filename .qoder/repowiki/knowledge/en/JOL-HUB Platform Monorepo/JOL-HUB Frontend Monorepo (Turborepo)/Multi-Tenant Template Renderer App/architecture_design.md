The app is organised as a three-layer composition pipeline. At the top, `src/lib/template-registry.ts` maps each STEP-5 vertical (church, diocese, deanery, funeral, cleaning) to a lazy-imported template component in `src/templates/`, with an optional admin `templateOverride` gated by the `template-override` feature. Each template renders a `PageComposer` (`src/lib/page-composer.tsx`) that iterates over the validated `PageConfig.modules` in JOL-controlled order, wrapping each module in layout-specific containers. The actual rendering is delegated to `src/modules/registry.ts`, which maps `ModuleType` strings to server-side React components plus a `requiredFeature` entitlement; `PageComposer` filters out modules whose features are not present on the resolved tenant. The editor subsystem (`src/components/editor/*` + `src/lib/editor/*`) writes draft content through Next.js Route Handlers under `src/app/api/editor/*`, which persist changes for human moderation before publishing. Shared runtime helpers in `src/lib/` (tenant resolver, i18n, SEO, JSON-LD, rate limiting, logger) are consumed uniformly by templates, modules, and API routes, while e2e tests in `e2e/` exercise the full rendered surface.
