Each file under this directory is a default-exported server component conforming to the `ModuleProps` contract defined in `types.ts` (tenant, locale, content, settings, layout, basePath). Modules are pure presentational adapters: they coerce the untyped `content`/`settings` records into typed shapes and delegate rendering to shared UI primitives from `@jol-hub/ui/components/composite`. The `registry.ts` file is the single entry point that imports every module, pairs it with an optional `requiredFeature` string, and exposes `MODULE_REGISTRY`, `getModuleComponent()`, and `isModuleEntitled()` so the page composer can resolve modules by `ModuleType` and gate commercial features (e.g. `gallery`, `contact-form`, `donations`) against tenant features. Commercial modules are kept as server components; their interactive children (Gallery lightbox, ContactForm, DonationWidget) are `'use client'` and split lazily by Next.js, keeping server-module code out of the client bundle.
