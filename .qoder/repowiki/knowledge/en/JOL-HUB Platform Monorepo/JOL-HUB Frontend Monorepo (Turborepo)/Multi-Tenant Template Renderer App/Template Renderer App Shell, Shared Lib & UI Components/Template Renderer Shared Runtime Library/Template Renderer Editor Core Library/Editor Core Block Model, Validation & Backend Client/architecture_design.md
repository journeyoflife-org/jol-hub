Three cohesive files form the editor core layer with a clear dependency direction: `blocks.ts` is the single source of truth for the domain model (`EditorBlock`, `EditorDraft`, `TextMark`, `TextLink`) and enforces the allowlist of editable block types plus hard limits (max blocks/images/text/image size) via pure functions like `validateDraft`. `diff.ts` depends only on `blocks.ts` and provides an id-based structural diff between two block lists, producing `BlockChange` records used by revision history and moderation before/after views. `editor-api.ts` depends on both `blocks.ts` and the sibling `moderation` module to wrap all `/api/v1/editor/*` endpoints behind an `EditorApiClient` class; it centralizes tenant isolation via the `X-Tenant` header, classifies HTTP errors into a discriminated union (`unconfigured`/`validation`/`auth`/`server`/`network`), and applies idempotent GET retry while deliberately avoiding auto-retry on mutations to prevent duplicate moderation submissions. The module exposes no UI — it is a pure, testable library consumed by higher-level editor orchestration code.
