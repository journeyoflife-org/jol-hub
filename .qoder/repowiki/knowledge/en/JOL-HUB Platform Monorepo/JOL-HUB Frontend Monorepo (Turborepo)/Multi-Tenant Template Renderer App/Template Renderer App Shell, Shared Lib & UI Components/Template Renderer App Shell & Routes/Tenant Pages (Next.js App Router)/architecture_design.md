Routes are nested under Next.js App Router segments `[locale]/[tenant]/...`, so every request first passes through the tenant_layout_and_root shell (layout.tsx/page.tsx/error.tsx/not-found.tsx) which resolves the tenant, builds i18n catalogs and chrome, then delegates to sibling page folders: tenant_static_pages (about/contact/accessibility-statement), tenant_content_listings (events/news/services with their own `[slug]` detail routes), plus admin/editor/profile/admin/moderation entry points. Cross-child wiring happens via shared PageComposer and fixture-first data resolution used by both static and listing pages, while the parent layout injects Header/Footer/LocaleSwitcher around all tenant routes.
