Three sibling route groups under `app/[locale]/[tenant]` — `events/`, `news/`, `services/` — each exposing a list page (`page.tsx`) and an optional detail page (`[slug]/page.tsx`). Every page is a server component that resolves the tenant via `resolveTenantRoute`, then checks for a fixture override through `renderFixtureRoute`; if no fixture exists it falls back to dynamic collection data from `@/lib/collections` (`getEvents`, `getNews`, `getServices`, plus their item getters). Lists use shared chrome components (`CollectionPageHeader`, `CategoryFilter`, `CollectionEmptyState`, `Pagination`) and `@/lib/collection-view` helpers to read `searchParams`-driven filters (view, when, category, q, page) so all navigation is pure `<a>`/form links. Detail pages perform closed lookups and call `notFound()` for missing slugs. Each route declares its own Next.js cache strategy: events and services use `dynamic = 'force-dynamic'` because pricing/availability are time-sensitive; news uses ISR with `revalidate = 60` (list) / `300` (detail). SEO is produced via `buildTenantMetadata` plus `JsonLd` emitting `breadcrumbEntity`, `itemListEntity`, `eventEntity`, `articleEntity`, or `serviceEntity`. UI cards come from `@jol-hub/ui/components/composite` and receive a tenant vertical prop via `themeVerticalFor` to style them per template theme.
