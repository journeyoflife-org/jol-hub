The module is organized as a flat collection of reusable React components grouped by feature domain under `auth/`, `commerce/`, `crm/`, `editor/`, with each subdirectory exposing a barrel `index.ts` that re-exports public APIs and documents the step-numbered integration boundary (STEP 8–16). The central `TemplateRenderer.tsx` is the entry point: it resolves a layout family and accent from `lib/layout-families` based on the tenant's `vertical`, then dispatches each `ContentBlock` in `page.contentBlocks` through a single `BlockView` switch statement (`hero`, `text`, `keyValue`, `schedule`, `list`, `stats`, `cta`) — new block types are added by extending this switch. Feature components depend outward on shared packages (`@jol-hub/ui`, `@jol-hub/commerce`, `@jol-hub/i18n`, `@jol-hub/seed-data`, `@jol-hub/observability`) and on app-level libs (`@/lib/auth`, `@/lib/tenant-context`, `@/lib/error-tracking`) but never on page routes, keeping them mountable anywhere. Cross-cutting concerns live as top-level client components: `ObservabilityClient.tsx` and `WebVitals.tsx` bootstrap telemetry gated by cookie consent, while `SharedCompliancePage.tsx` renders tenant-independent GDPR pages using ICU-formatted messages. Stateful features like commerce use a Context + localStorage pattern (`cart-context.tsx`) scoped per tenant slug to isolate data across tenants.
