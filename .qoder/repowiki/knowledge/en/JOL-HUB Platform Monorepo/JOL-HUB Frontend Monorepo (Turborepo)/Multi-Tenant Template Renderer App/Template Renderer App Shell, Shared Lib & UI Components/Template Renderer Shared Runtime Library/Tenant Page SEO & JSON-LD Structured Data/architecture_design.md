Three cooperating files form a layered SEO pipeline inside the template-renderer app:
- `seo.tsx` is the server-only bridge that resolves the public origin from `next/headers` (`x-forwarded-host` / `host`, with proxy-safe protocol selection) and delegates to the external `@jol-hub/seo` core for absolute canonical + reciprocal hreflang generation via `buildHreflangSet`. It exposes `resolveSeoOrigin`, `absoluteUrl`, `buildSeoAlternates`, and `buildTenantBaseMetadata` consumed by layouts.
- `page-seo.ts` composes per-page `Metadata` objects for tenant routes using `buildSeoAlternates` plus localized title/description and OG/Twitter card fields; it also provides helpers (`tenantDisplayName`, `tenantTagline`) that prefer fixture data over registry data via `pickLocalized`.
- `json-ld.tsx` is a pure React component + builder library that emits `<script type="application/ld+json">` blocks without pulling in `schema-dts` (to keep offline builds working). It defines a narrow `JsonValue` union and factory functions for each schema.org entity type (`organizationEntity`, `websiteEntity`, `webPageEntity`, `breadcrumbEntity`, `articleEntity`, `eventEntity`, `serviceEntity`, `itemListEntity`) plus an `organizationTypeFor` mapper driven by the tenant vertical. All URLs passed into these builders are expected to be absolute (enforced by callers via `absoluteUrl`).
Dependency direction: `page-seo.ts` → `seo.tsx` → `@jol-hub/seo`; `json-ld.tsx` is independent and consumed by page components alongside the metadata layer. Security boundary: builders only accept public-facing fields (never internal `schema`), and alternates are scoped to the same tenant slug to prevent cross-tenant enumeration.
