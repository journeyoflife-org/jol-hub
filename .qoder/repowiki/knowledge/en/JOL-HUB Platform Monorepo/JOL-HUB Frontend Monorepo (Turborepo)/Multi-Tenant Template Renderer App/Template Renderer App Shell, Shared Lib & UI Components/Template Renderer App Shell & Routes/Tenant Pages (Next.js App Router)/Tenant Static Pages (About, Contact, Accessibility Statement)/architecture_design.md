Each route lives under `src/app/[locale]/[tenant]/<route>/` as a Next.js App Router page that resolves tenant context via `resolveTenantRoute`, then follows a consistent two-phase render: first attempt to serve a fixture-provided component via `renderFixtureRoute(fixture, '/<route>', basePath)`; if no fixture exists, fall back to a parsed page config built from `buildAboutConfig`/`buildContactConfig` in `@/lib/page-defaults` and composed by `PageComposer`. Metadata is generated per-route using `buildTenantMetadata` plus `tenantDisplayName`/`tenantTagline`, and structured data is injected via `<JsonLd>` with `organizationEntity` and `webPageEntity` (`AboutPage`, `ContactPage`). The `about` and `contact` routes declare `revalidate = 3600` to express SSG intent (realized at the data-cache layer due to root-layout language constraints). `loading.tsx` skeletons are provided only at the route level (not at `[tenant]`) to avoid soft-200 suppression of `notFound()` on collection routes. The `accessibility-statement` page is self-contained boilerplate that interpolates the tenant name into i18n sections and links to `/contact` for feedback.
