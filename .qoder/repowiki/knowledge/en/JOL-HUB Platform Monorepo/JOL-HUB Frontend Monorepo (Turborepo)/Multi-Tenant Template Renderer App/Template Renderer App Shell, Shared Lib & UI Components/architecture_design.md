The three sub-trees form a layered pipeline: `app/` defines Next.js routes (tenant-resolved layouts, per-tenant page segments, and server-side API routes) that import from `lib/`, which implements cross-cutting concerns (tenant resolution via `tenant-context.tsx`/`tenant-resolver.ts`, route dispatch through `route-dispatch.tsx`, page composition via `page-composer.tsx`/`template-registry.ts`, SEO/JSON-LD, editor client/server integration, and content loading). `components/` provides reusable React widgets (auth, commerce, CRM, editor, observability) consumed by both the shell and composed pages. The `lib/route-dispatch.tsx` is the central wiring point where the app shell hands off to the lib's dispatcher, which then selects a template and renders it with the appropriate components, keeping the route layer thin and business logic in `lib/`.
