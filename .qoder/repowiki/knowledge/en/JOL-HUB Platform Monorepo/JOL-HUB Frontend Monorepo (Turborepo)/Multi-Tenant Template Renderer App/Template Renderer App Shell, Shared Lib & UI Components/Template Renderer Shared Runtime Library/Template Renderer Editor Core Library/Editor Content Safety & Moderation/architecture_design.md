Three cooperating pure-function modules under `src/lib/editor/` that together enforce defense-in-depth for tenant page content:
- `moderation.ts` declares the moderation domain model (`ModerationItem`, `AiModerationResult`, `MediaUploadState`, `ModerationDecision`) and helpers (`decisionRequiresReason`, `isArt9Item`). It documents the pipeline boundary: the frontend never calls LLMs directly; AI screening is advisory and every decision is audit-logged. GDPR Art. 9 items are routed to a dedicated `art9-review` queue.
- `sanitize.ts` implements escape-first rendering: `escapeHtml` on every text run, a closed `SANITIZED_ALLOWED_TAGS` set mirrored by DOMPurify in the caller, and `isSafeUrl` which rejects `javascript:`/`data:`/`vbscript:` schemes, non-https URLs, and hosts not in `DEFAULT_URL_ALLOWLIST`. `renderBlockHtml` emits only `<p>`, `<h2>`, `<blockquote>`, `<strong>`, `<em>`, `<a>`, `<hr>`, `<br>`, `<button>`, `<div>`, `<span>`, `<img>` from `EditorBlock` input, plus prohibited-pattern scanning (email, phone, bare URLs) via regexes.
- `validation.ts` provides Zod schemas (`blockSchema`, `draftBodySchema`, `decisionBodySchema`, `uploadBodySchema`) that mirror `blocks.ts` limits and reuse `isSafeUrl` to reject unsafe links at the API edge. Per-type refinements enforce length caps, required alt text, and safe button hrefs.
Dependency direction: `validation.ts` imports from both `blocks.ts` and `sanitize.ts`; `sanitize.ts` depends only on `blocks.ts`; `moderation.ts` is self-contained and defines the contract consumed by the rest of the editor. No module mutates global state — all functions are pure.
