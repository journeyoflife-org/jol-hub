Three Next.js App Router files at `src/app/` form the top of the template-renderer app:
- `layout.tsx` is the root layout: it imports global CSS (tokens + globals), injects `THEME_INIT_SCRIPT` before first paint to prevent theme FOUT, wraps children in `ThemeProvider`, sets `html lang` from the middleware-set `x-locale` header (validated via `isSupportedLocale`, falling back to `DEFAULT_LOCALE`), and mounts consent-gated `WebVitals` and `ObservabilityClient` components. Metadata uses a `%s | {tenant}` title template so child layouts can white-label titles.
- `page.tsx` is the root route (`/`). It is forced dynamic (`dynamic = 'force-dynamic'`) and calls `resolveCurrentTenant()` from `@/lib/tenant-resolver`; on success it redirects to `/{locale}/{tenantId}`, otherwise calls `notFound()`. This acts as a safety net when middleware does not rewrite the URL.
- `not-found.tsx` is the global 404 handler. It deliberately exposes no tenant information (security constraint) and renders localized strings via `getMessages(locale)` + `translate(...)` for `errors.notFoundTitle` / `errors.notFoundBody`.
Dependency direction is one-way outward: this module depends on shared packages (`@jol-hub/ui`, `@jol-hub/i18n`) and local components (`components/WebVitals`, `components/ObservabilityClient`, `lib/tenant-resolver`) but has no sibling routes — it is consumed by Next's routing layer only.
