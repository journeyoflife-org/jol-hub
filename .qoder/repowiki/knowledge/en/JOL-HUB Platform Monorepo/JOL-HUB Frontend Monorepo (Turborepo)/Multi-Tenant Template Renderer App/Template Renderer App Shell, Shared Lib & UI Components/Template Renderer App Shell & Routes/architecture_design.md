The `app/` directory is split into three cooperating layers: root layout files (`layout.tsx`, `page.tsx`, `not-found.tsx`) provide the global HTML shell and resolve the current tenant via headers/subdomain before redirecting into `[locale]/[tenant]`; under `[locale]/[tenant]` the tenant pages compose layouts, static pages, and content listings (events, news, services) into a multi-tenant frontend; under `api/` Next.js server routes implement auth, CRM, editor, telemetry, health, and perf endpoints that proxy browser calls to backend services while enforcing validation, tenant isolation, rate limiting, and pilot-mode fallbacks. The three layers share the same Next.js App Router conventions — route groups, catch-all segments (`[[...slug]]`, `[...slug]`), and `loading.tsx`/`error.tsx` boundaries — so the root layer can hand off any request to either a tenant page or an API handler without framework-level coupling.
