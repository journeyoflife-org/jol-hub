- Route handlers validate all inputs first (Zod `safeParse` + regex patterns for tenant/page/item IDs) and return `{ error: 'validation' }` with 400 before checking configuration availability, ensuring malformed requests are always client errors regardless of backend state.
- Backend integration points are gated by `isXxxConfigured()` guards followed by `serverXxxClient()` instantiation, returning `{ error: 'unconfigured' }` with 503 when optional planes (CRM, editor, auth) are not configured, enabling pilot mode without crashing.
- Backend call results use a discriminated union `{ ok: true, data } | { ok: false, error: { kind, ... } }` where `error.kind` values (`auth`, `validation`, `rate-limit`, `auth-rotation`) are mapped to specific HTTP status codes (403, 400, 429, 503, 502) in a switch-like block.
- Telemetry endpoints (`/api/perf`, `/api/telemetry/*`) enforce a privacy contract by validating payloads with Zod, re-redacting values via `redactValue`, rate-limiting by IP, and forwarding to `BACKEND_API_URL` only when configured — otherwise responding 204 so RUM never surfaces errors to the client.
- Tenant isolation is enforced by extracting `tenantSlug` from query params or body, validating it against `SLUG_PATTERN` plus a length cap, and passing it through to backend clients which apply RBAC/RLS server-side.
- Optional integrations expose a consistent `dynamic = 'force-dynamic'` export and probe-only semantics (e.g. health checks time out at 1.5s, do not store credentials or internals) so load balancers can safely poll without coupling to third-party availability.
