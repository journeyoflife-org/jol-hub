Each file under `src/app/api/` is a Next.js App Router route handler that acts as a thin, same-origin gateway between the browser and backend services — the browser never sees hub-backend URLs or credentials. The module is organized by domain subdirectories: `auth/[...nextauth]` delegates to NextAuth with lazy option building guarded by `isAuthConfigured`; `crm/deals` and `crm/leads` are read/write proxies over `serverCrmClient()` from `@/lib/bitrix-client`; `editor/{media,moderation,pages}` handle media upload registration, moderation queue decisions, and draft/publish flows via `serverEditorClient()`; `health` aggregates dependency checks (backend, auth, CRM, editor, payments) using `@jol-hub/observability`; `perf` and `telemetry/{errors,perf}` accept client metrics and errors, validate them with Zod, rate-limit by IP, and forward to `BACKEND_API_URL` when configured. All handlers follow a strict validation-first order (400 before 503), map backend error kinds (`auth`, `validation`, `rate-limit`, `auth-rotation`) to HTTP status codes, and return pilot-mode 204 responses when no backend is configured so reporting never fails visibly.
