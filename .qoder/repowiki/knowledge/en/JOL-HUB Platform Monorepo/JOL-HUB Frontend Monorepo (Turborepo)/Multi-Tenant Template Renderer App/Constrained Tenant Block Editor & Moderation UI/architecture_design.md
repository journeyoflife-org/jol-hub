Two-layer split inside the module: `src/components/editor/` holds React client components (`BlockEditor`, `MediaUploader`, `ModerationQueue`) re-exported via an `index.ts` barrel; `src/lib/editor/` holds pure, unit-testable primitives (block model, constraints, sanitization, diff, validation, moderation helpers, and an `EditorApiClient`) also re-exported through a single barrel. Dependency direction is strictly one-way — components import from `@/lib/editor` but never the reverse. The editor enforces a closed block allowlist (`ALLOWED_BLOCK_TYPES` in `blocks.ts`) so no raw HTML surface exists; rich text is stored as plain text plus structured marks/links, rendered escape-first by `sanitize.renderDraftHtml`, then passed through DOMPurify with a locked tag list for preview. Autosave polls `/api/editor/pages/:id/draft` every 30s, publish POSTs to `/publish` which queues a moderation item rather than going live, and a 2-hour session timeout forces re-auth. `MediaUploader` validates files client-side (type, size ≤ 2MB, dimensions ≤ 8192px, required alt text) and posts metadata to `/api/editor/media`, entering quarantine until approved. `ModerationQueue` polls `/api/editor/moderation` every 30s, displays AI screening results and malware scan state, and dispatches approve/reject/request-changes/escalate decisions back to `/api/editor/moderation/:id`. All server-bound payloads are additionally validated on the API proxy using Zod schemas in `validation.ts` mirroring the client limits.
