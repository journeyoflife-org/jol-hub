Two-layer composition inside the module. `base-template.tsx` defines `BaseTemplate`, which owns cross-cutting concerns identical across all verticals: applying a `data-vertical` attribute plus a CSS custom property accent via `verticalThemeFor`/`verticalAccentStyle`, emitting baseline JSON-LD (`Organization` subtype + `WebSite`) through `JsonLd`, and rendering the page's module composition via `PageComposer` (or falling back to `buildVerticalHomeConfig`). It also exports `VerticalHomeTemplate`, a shared renderer that either renders fixture/backend content via `TemplateRenderer` or falls back to the base template with a default composition. Each vertical file (`church-template.tsx`, `diocese-template.tsx`, `deanery-template.tsx`, `cleaning-template.tsx`, `funeral-template.tsx`) is a thin wrapper that re-exports `VerticalHomeTemplate` as its default — differentiation (accent color, hero variant, schema.org type, SEO copy) is driven entirely by `tenant.vertical` resolved in shared libs, so no per-vertical logic is duplicated. The templates are consumed by the template registry (`@/lib/template-registry`) and rendered as Next.js server components; header/footer chrome lives outside this scope in `app/[locale]/[tenant]/layout.tsx`.
