The frontend is organized as a pnpm workspace with two top-level scopes: `apps/` holds four independent Next.js 14 applications (admin-dashboard, master-site, parish-template, template-renderer) plus a `react/` demo app, while `packages/` contains framework-agnostic libraries (auth, commerce, i18n, observability, seo, ui, tenant-resolver, etc.). Turborepo (`turbo.json`) defines shared tasks (`build`, `lint`, `type-check`, `test`, `dev`, `clean`) with dependency ordering so package builds precede app builds via `dependsOn: ["^build"]`. Each app is self-contained with its own `next.config.js`, `tailwind.config.ts`, `postcss.config.mjs`, and `tsconfig.json`, but all consume shared packages from `packages/*` through workspace resolution. The root `package.json` scripts (`build`, `build:all`, `build:infrastructure`, `build:entities`, `build:packages`, `dev`, `test`, `release`) are the single entry point that dispatches to Turborejo tasks, which in turn run per-app or per-package commands. Apps communicate only through shared packages and their own API routes; there is no cross-app runtime coupling.
