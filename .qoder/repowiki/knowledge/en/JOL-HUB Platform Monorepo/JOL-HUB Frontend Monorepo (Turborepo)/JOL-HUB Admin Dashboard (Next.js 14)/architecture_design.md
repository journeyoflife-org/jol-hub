Built as a Next.js 14 App Router application with route groups: `(auth)` for login/error pages, `(dashboard)` for authenticated sections, `api/` for server routes (NextAuth credentials, Bitrix24 webhooks/jobs/status), and a top-level `/dashboard` layout. The root `src/app/layout.tsx` wraps every page in a `Providers` component that composes NextAuth `SessionProvider`, TanStack Query `QueryClientProvider`, and `next-themes` ThemeProvider; a `TokenSync` effect pushes the session access token into a module-scoped variable consumed by `src/lib/api.ts`. Authentication is implemented via `src/app/api/auth/[...nextauth]/route.ts` using NextAuth credentials provider against a Django backend (`NEXT_PUBLIC_API_URL`), with JWT strategy, automatic refresh, and mock auth fallback in development. Route-level protection uses `src/middleware.ts` (NextAuth `withAuth`) plus per-route `AuthGuard`/`CountryGuard` components to enforce SOC2 CC6.1 role-based access and GDPR Article 44 data-residency checks. Domain logic lives in `src/lib/auth.ts` defining a 4-tier hierarchy (`super` → `country` → `diocese` → `facility`) with `canAccessEntity`, `canViewAggregatedData`, `hasPermission`, and role-to-tier mappings. UI is organized under `src/components/{auth,bitrix24,charts,compliance,entities,layout,ui}` with Radix primitives and Tailwind CSS; charts use Chart.js + Recharts. Data fetching is centralized in `src/lib/api.ts` which exposes typed client modules (`dashboardApi`, `parishesApi`, `usersApi`, `donationsApi`, `analyticsApi`, `aiApi`, `authApi`) over a single `fetchApi` wrapper that injects Bearer tokens and normalizes responses. Shared state and hooks live in `src/hooks/` (`useBitrix24`, `useCountry`, `useGDPR`, `useHierarchy`) and `src/types/` define all domain models. Build-time configuration in `next.config.js` transpiles workspace packages (`@jol-hub/ui`, `@jol-hub/auth`, `@jol-hub/i18n`), sets security headers, and configures image domains.
