Built on Next.js 14 App Router with a layered client-side architecture: `src/app/` defines routes using route groups (`(auth)` for public pages) and a root `layout.tsx` that wraps every page in `AuthProvider`. Authentication state lives in `src/context/AuthContext.tsx`, which performs silent session rehydration on mount (in-memory access token → `/me`, or refresh cookie → `/auth/refresh/` + `/me`) and schedules proactive token refresh at 80% of the access-token lifetime. Route-level protection is enforced by `src/middleware.ts`, an Edge middleware that redirects unauthenticated requests to `/login?next=...` based on the presence of the `jol_refresh` cookie; client-level guards are provided via `AuthGuard` component and the `useRequireAuth` hook (with optional role checks). HTTP concerns are centralized in `src/lib/apiClient.ts`, an Axios instance that attaches Bearer tokens from an in-memory store and implements a single-flight 401 refresh interceptor queuing concurrent requests. Token persistence is split between an in-memory access token (never written to disk) and a refresh token stored via `js-cookie` with `Secure` + `SameSite=Strict` flags. Domain logic is split into `lib/authApi.ts` (login/logout/register/fetchMe), `types/api.ts` (Zod-backed schemas), and reusable UI primitives under `components/` plus shared hooks under `hooks/`.
