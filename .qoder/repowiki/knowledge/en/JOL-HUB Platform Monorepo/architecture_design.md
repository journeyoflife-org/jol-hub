The root acts as the authoritative integration point for a multi-tenant ecclesiastical platform spanning ~400k tenant websites across 27+ EU countries. It wires together six child domains — backend (Django/Celery), frontend (Turborepo/Next.js), data_pipelines (Airflow/dbt/GDPR ETL), infra (Terraform/Kubernetes/Helm), docs (ADRs/spoke templates), and country_configs (Baltic liturgical & compliance packs) — plus scripts_and_tools for compliance enforcement and scaffolding. `docker-compose.yml` is the local orchestration entrypoint that boots PostgreSQL, Redis, MongoDB, the Django dev server, Celery worker, and Celery Beat so all children share one runtime stack. The README documents the GitFlow branching model, GPG-signed commits, CODEOWNERS-based security review gates, and the boundary between this repo and satellite repositories under `/opt/jol/repos/`. Cross-child contracts are enforced via shared environment variables (`DATABASE_URL`, `REDIS_URL`, `MONGODB_URI`, `DJANGO_SECRET_KEY`) and by keeping each child self-contained while the root only declares how they compose locally and in CI via `.github/workflows/`.
