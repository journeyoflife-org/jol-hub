Standard Django REST Framework app under `apps.analytics` with a flat layering: `models.py` defines the raw event model `PageView` (tied to `Organization`, with anonymized IP, session tracking, and explicit consent fields) and the pre-aggregated `DailyStats` model; `views.py` exposes three read-only DRF `APIView`s (`AnalyticsOverviewView`, `DailyStatsListView`, `TopParishesView`) mounted via `urls.py` at `/api/v1/analytics/{overview,daily,top-parishes}/`; `serializers.py` provides read-only DRF serializers for both models plus custom response schemas. Consent enforcement is centralized in module-level helpers (`check_analytics_consent`, `get_organizations_with_consent`) that consult `ConsentSettings` before any data is returned. Tenant isolation is enforced at the model layer by overriding `save()` to call `_validate_tenant_context()`, which lazily imports `apps.crm.middleware.get_current_tenant_id` and raises `ValidationError` when `organization_id` mismatches the active tenant. The `TopParishesView` additionally applies k-anonymity (threshold from `settings.GDPR_K_ANONYMITY_VALUE`, default 5) by rounding counts and bucketing small organizations into an 'Other' category. All query parameters are validated through dedicated helpers (`validate_organization_id`, `validate_date_param`, `validate_date_range`, `validate_positive_int`) to prevent injection and DoS via large date ranges.
