Single-purpose Django app exposing one POST route (`/internal/v1/payment-events`) defined in `urls.py` and handled by `views.receive_payment_event`. The request pipeline follows the contract v1.0.0 verification order: feature-flag gate (`PAYMENT_EVENTS_ENABLED`), required header check (`X-Product`, `X-JOL-Timestamp`, `X-JOL-Signature`), replay-window validation against `PAYMENT_EVENTS_REPLAY_WINDOW_SECONDS`, HMAC-SHA256 signature verification using `HUB_PAYMENT_DELIVERY_KEY`, product routing (accepts only `hub`), JSON parse + schema whitelist validation against `REQUIRED_FIELDS` and `ALLOWED_EVENT_TYPES`, idempotent dedupe on `event_id` (unique index), then `persist-before-process` insertion into `PaymentEvent`. The model in `models.py` mirrors the contract's whitelist exactly with no personal data columns. A self-contained test module (`test_receiver.py`) uses pytest fixtures to inject settings and re-implements the signing algorithm to drive both happy-path and error-contract cases without hitting a live backend.
