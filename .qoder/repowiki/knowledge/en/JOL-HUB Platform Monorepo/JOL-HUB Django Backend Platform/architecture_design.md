The `django/` directory is the Django project root (`core/`) whose `settings.base` registers every domain app under `apps/` and mounts their URL namespaces from `core/urls.py`; each app follows the same DRF pattern of `models → serializers → views → urls`. Cross-app communication happens through shared Django models (e.g. `organizations.Organization` as the tenant boundary), Django signals/signals in `crm.signals`, and async work dispatched via Celery tasks defined in `core/celery.py` and consumed by workers. External systems are isolated in `integrations/bitrix24/` (SDK + webhook handlers) and wired into the CRM/integrations apps through service classes (`bitrix24_service.py`, `client.py`). Payment and webhook ingress points live in dedicated apps (`payment_events`, `integrations`) that persist events and enqueue downstream sync tasks. Multi-tenancy is enforced centrally: `core.permissions`, `crm.middleware`, and `crm.tenant_verification` derive the active organization from the request context so all other apps scope queries to the current tenant.
