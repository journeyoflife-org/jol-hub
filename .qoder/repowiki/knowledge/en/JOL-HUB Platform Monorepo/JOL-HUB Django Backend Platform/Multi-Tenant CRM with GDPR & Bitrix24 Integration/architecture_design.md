The app is organized as a standard Django reusable app under `apps/crm/` with clear layering:
- Models (`models.py`) define the domain: an abstract `CRMTenantModel` base that adds `organization`, `data_classification`, legal hold, consent tracking, Bitrix24 sync fields, and a tamper-evident `record_hash` chain; concrete entities `Contact`, `Lead`, `Deal`, plus `AuditEntry` and `DataSubjectRequest`. A custom `CRMTenantManager` auto-filters queries by `organization_id` using the current tenant context.
- API (`api/views.py`, `api/serializers.py`, `api/urls.py`) exposes DRF `ModelViewSet`s wrapped in a `TenantIsolatedViewSetMixin` that injects `organization_id` on create, filters by tenant, and validates object ownership via `TenantDataAccessValidator`. Sensitive endpoints use per-operation throttles (`GDPRExportThrottle`, `FinancialThrottle`).
- Tenant isolation middleware (`middleware.py`) runs `TenantContextMiddleware` to extract tenant from JWT claims / `X-Tenant-ID` header / user default org, stores it in thread-local storage, and provides `get_current_tenant_id()` consumed by managers, views, and services.
- External integration (`bitrix24_service.py`) wraps `integrations.bitrix24.Bitrix24Client` behind a `Bitrix24ClientFactory` with per-tenant client caching, a circuit breaker (`CircuitBreakerState`), field mapping tables, and both async (`CRMBitrix24Service`) and sync (`CRMBitrix24ServiceSync`) entry points. Management commands in `management/commands/sync_bitrix24.py` drive batched sync jobs.
- Audit trail (`audit_logger.py`, `signals.py`) uses Django signals (`pre_save`/`post_save`/`post_delete`) on Contact/Deal/DataSubjectRequest to compute field-level diffs and persist `AuditEntry` rows with SHA-256 hash chains and HMAC signatures; `ComplianceAuditLogger` centralizes GDPR Art. 15-22, PCI-DSS, and SOC2 event types.
- Security utilities (`security.py`) provide Fernet-based PII encryption, input sanitization, and rate limiting helpers; `observability/metrics.py` emits Prometheus-style metrics.
Dependency direction is one-way: API → models + middleware + audit_logger; bitrix24_service → models + middleware; management commands → bitrix24_service; no cross-imports back into api or middleware from lower layers.
