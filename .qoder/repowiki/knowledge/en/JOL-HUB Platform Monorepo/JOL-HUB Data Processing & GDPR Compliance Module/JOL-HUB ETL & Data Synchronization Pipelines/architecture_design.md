The module is organized as a package under `data/src/pipelines/` with three sibling sub-packages, each exposing a curated public API via its `__init__.py`:
- `country_sync/`: A template-driven per-country sync framework. `template_sync.py` defines `CountrySyncTemplate` plus a `CountrySyncConfig` dataclass; concrete implementations like `lt_sync.py` (`LithuaniaSyncPipeline`) and `lv_sync.py` subclass the template to implement country-specific `_fetch_*`, `_validate_*`, and `_load_*` steps while reusing shared audit and compliance hooks. The `__all__` exports only the concrete pipeline classes.
- `entity_import/`: Bulk onboarding of parishes, priests, and organizations. `bulk_loader.py` provides an abstract `BulkLoader` base class (batched iteration, progress tracking, rollback, PII anonymization) extended by `ParishBulkLoader` and `DonationBulkLoader`; `csv_validator.py` supplies schema-driven validation (`CSVValidator`, `CSVSchema`, `ENTITY_SCHEMAS`) that enforces required columns, consent timestamps, and PII encryption before import.
- `donation_analytics/`: Aggregation pipeline (`DailyAggregationPipeline`) producing `DonationMetrics` dataclasses, grouping donations by country/organization and suppressing groups below a k-anonymity threshold.

All pipelines depend outward on shared infrastructure in the parent `src/` package: `src.audit.AuditLogger`/`AuditEvent` for every start/end operation, `src.config.DataClassification` for GDPR classification, `src.validators.DataValidator` for row-level validation, and `src.gdpr.anonymizer.KAnonymizer` for k-anonymization. Dependency direction is strictly inward — pipelines consume `src.*` utilities but never the reverse. Each pipeline follows a consistent lifecycle: construct with optional config + audit logger → log start event → process batches → log completion event with stats.
