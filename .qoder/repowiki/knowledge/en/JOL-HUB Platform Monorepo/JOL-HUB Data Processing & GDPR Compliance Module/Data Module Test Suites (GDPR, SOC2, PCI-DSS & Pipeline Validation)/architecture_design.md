Flat pytest package under `data/tests/` with one test file per concern: `test_pipelines.py` verifies ETL template and bulk-loader importability; `test_processors.py` exercises `src.processors`, `src.validators`, `src.audit`, and GDPR processing-activity registry; `test_gdpr.py` drives `src.gdpr` anonymizer, retention manager, and ROPA generator against `src.config` enums; `test_compliance.py` is a large cross-cutting suite organized into classes (`TestGDPRCompliance`, `TestSOC2Compliance`, `TestPCIDSSCompliance`, `TestAuditLogIntegrity`, `TestMultiTenantIsolation`, `TestSecretsManagement`) that assert on source files across the repo root via a `project_root` fixture pointing at `Path(__file__).parent.parent.parent`; `test_dependency_guard.py` enforces ADR-0005 by scanning installed distributions and `backend/*requirements.txt` for any Stripe footprint. Tests are self-contained — they either import from `src.*` or read filesystem paths to assert presence of required code/config, so there is no shared test harness beyond the standard `pytest` fixtures.
