The module is organized as a layered DBT transformation pipeline under `data/src/transformations/` with three distinct tiers: `staging/` (raw-to-cleaned deduplication, e.g. `stg_entities.sql`), `intermediate/` (derived analytical aggregates like donation trends with k-anonymity filters), and `marts/` (business-facing reports such as canonical compliance scores and country-level metrics). Each model declares its materialization target (`view` or `table`) and output schema via the `{{ config(...) }}` macro and references upstream sources through `{{ source('raw', ...) }}` and `{{ ref('...') }}`, establishing a strict dependency direction from staging → intermediate → marts. A separate `data/sql/` directory holds non-DBT operational SQL: `schema_setup/001_initial_schema.sql` provisions PostgreSQL extensions, audit, GDPR request, retention, and processing-activities tables with row-level security; `audit_queries/gdpr_compliance.sql` provides ad-hoc queries against those tables. PII handling is gated by the `include_pii` variable, and all aggregations enforce k-anonymity (k=5) before exposure in public-facing marts.
