A dbt v2 project (`dbt_project.yml`) named `jol_hub` organized into two model layers under `models/`: `staging/` (materialized as views in the `staging` schema) for cleaning and masking raw source tables `raw.users` and `raw.donations`, and `marts/` (materialized as tables in the `gdpr_compliance` schema) producing business-level outputs — a data subject export view for GDPR Art. 20 portability and a compliance report for Art. 30 processing activity metrics. Source definitions and column-level tests live in `models/staging/schema.yml`. The project declares global variables for GDPR retention periods and EU country lists, and uses per-model `{{ config }}` blocks to set materialization, target schema, and tags. Database connectivity is configured via `profiles.yml` with `dev` and `prod` targets reading connection parameters from environment variables (`DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD`, `DB_NAME`). Marts consume staging models exclusively through `{{ ref('...') }}`, enforcing a strict one-way dependency from marts → staging → raw sources.
