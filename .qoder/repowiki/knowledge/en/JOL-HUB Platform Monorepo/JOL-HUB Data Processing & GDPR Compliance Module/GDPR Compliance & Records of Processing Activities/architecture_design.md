The module is split into two sibling scopes. `data/src/gdpr/` contains the runtime compliance library: `anonymizer.py` implements k-anonymity via a `KAnonymizer` class with per-country thresholds (`COUNTRY_K_VALUES`) resolved from an ISO country code or `GDPR_K_ANONYMITY_VALUE` env var; `retention_manager.py` implements GDPR Art. 17 erasure and Art. 5(1)(e) storage limitation through a `RetentionManager` that consults a process-global `LegalHoldRegistry` (singleton accessed via `get_legal_hold_registry()`) before any deletion, logging every blocked attempt via `src.audit.AuditLogger`; `ropa_generator.py` defines the `ProcessingActivity` dataclass and a `ROPAGenerator` that serializes to JSON or Markdown and writes timestamped files under a configurable output directory; `entity_ropa.py` extends this by mapping each of the 10 JOL-HUB entity types (basilica, cathedral, diocese, deanery, church, protestant, orthodox, greek_catholic, funeral, cemetery) to entity-specific `ProcessingActivity` lists via a dispatch function `get_entity_processing_activities`, using a shared `_create_base_activity` helper. The package exposes its public API through `__init__.py`. `data/exports/ropa/lt/<entity>/` holds pre-generated ROPA JSON (and occasional `.markdown`) artifacts per entity instance — these are outputs consumed by auditors rather than generated at runtime. Dependency direction is one-way: `entity_ropa.py` imports `ProcessingActivity` from `ropa_generator.py`; `anonymizer.py` and `retention_manager.py` are independent utilities used by higher-level pipelines.
