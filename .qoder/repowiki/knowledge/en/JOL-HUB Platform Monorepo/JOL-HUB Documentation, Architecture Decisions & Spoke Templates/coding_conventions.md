- Architecture decisions are recorded as numbered ADR files in `docs/decisions/ADR-NNN-*.md` and cross-referenced from the append-only `DECISION-LOG.md`, where superseded entries are struck through rather than deleted to preserve audit trails.
- Compliance actions are paired with a signed-off decision row in the decision log and an independent artifact file under `docs/compliance/evidence/` named with a date stamp (e.g. `STEP18_EXECUTED.md`, `archive-purge-20260827.md`, `lt-flagon-payment-events.md`).
- Each spoke repo generated from the template enforces invariant checks via shell/TS scripts (`check-payment-boundary.sh`, `check-theme-literals.sh`, `check-secrets.sh`, `check-a11y-pages.ts`, `check-perf-budget.ts`) invoked from npm scripts and gated in CI workflows under `templates/reusable-workflows/`.
- Secrets in templates use SOPS with an `.sops.yaml` manifest and an `secrets/{common,critical,production}/encrypted/` directory layout; real values are never committed and only `.env.example` templates are tracked.
- Design specifications follow a numbered page convention (`docs/design/pages/NN-name.md`) that maps one-to-one to vertical landing pages, keeping page-level specs discoverable by index.
