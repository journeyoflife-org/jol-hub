The module is a flat documentation tree organized by concern rather than code: `architecture/` holds system-overview, data-flow, security-model, package-versioning/publish-runbook, and the hub-and-spoke topology decision (ADR-011); `decisions/` contains numbered ADRs plus an append-only DECISION-LOG that records ratified decisions, sign-offs, and open questions with explicit supersession chains; `compliance/` groups GDPR/DPIA policy docs under `compliance/` and time-stamped execution artifacts (push proofs, sweep proofs, archive purges) under `compliance/evidence/`; `design/pages/` enumerates 25 page-level design specs per vertical; `modules/` documents AI modules (pastoral assistant, FAQ chatbot); `seo/` captures international SEO and per-tenant sitemap/robots strategy; `commerce/` defines donation flow; `api/openapi-spec.yaml` is the machine-readable contract consumed by generators. The `templates/jol-frontend-repo-template/` subtree is a fully bootstrapped Next.js 14 + pnpm project (package.json pins Node ≥20, pnpm ≥10, Next 14.2.0, React 18) that every vertical spoke repo clones and runs `scripts/instantiate.sh {vertical} "{Display Name}"` against — it ships CI workflows (`reusable-workflows/*.yml`), guard scripts (`check-payment-boundary.sh`, `check-theme-literals.sh`, `check-secrets.sh`, `check-a11y-pages.ts`, `check-perf-budget.ts`), SOPS-encrypted secrets layout, and CODEOWNERS/CONTRIBUTING/SECURITY boilerplate. Dependency direction is one-way: spokes consume shared `@jol-hub/*` packages declared in the template's `package.json`; the template itself has no runtime dependency on the monorepo beyond the published registry. The `docs/payment-api-contract.md` serves as the normative boundary document referenced by both the payment-boundary guard workflow and the DPIA.
