Two sibling directories with no shared runtime:
- `scripts/` holds executable utilities invoked directly from the repo root. Shell guards (`check-payment-boundary.sh`, `check-theme-literals.sh`) use `grep -rIn` over the project tree to enforce ADR-0005 Model A (no Stripe SDK/keys in hub) via named VOCAB/RULEDOC exemption ledgers. Python entry points (`run_compliance_tests.py`, `run_tenant_verification.py`, `validate_entity_configs.py`) each add a sibling package to `sys.path` at import time (`data`, `backend/django`) and dispatch via `argparse` to test runners or validators; they produce text or JSON output and exit non-zero on failures. `setup-venvs.sh` provisions isolated virtual environments.
- `tools/qoder/` is a self-contained CLI framework: `qoder.py` defines a `QoderCLI` class with subparsers for `workflow`, `scaffold`, and `ropa` commands, delegating to workflow classes in `workflows/` (`GenerateParishSiteWorkflow`, `EntityScaffoldWorkflow`/`BulkEntityScaffold`, `ROPAGeneratorWorkflow`).
- `tools/mcp-*.py` are independent JSON-RPC 2.0 MCP servers (`mcp-compliance.py`, `mcp-postgres.py`, `mcp-bitrix24.py`) that read messages from stdin and write responses to stdout, declared in `requirements-mcp.txt`.
Dependency direction is outward-only: scripts/tools import into `data/` and `backend/django/` but never the reverse; there is no shared library between scripts and tools.
