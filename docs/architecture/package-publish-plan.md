# Package Publish Plan — Hub-and-Spoke Topology

> **Authoritative decision:** ADR-011 (2026-09-11). This document is the
> technical plan for making the 12 `@journeyoflife-org/*` packages publishable so
> the ten spoke repositories can consume them as versioned dependencies.

## Dependency Graph

```
Wave 0 (leaves — no internal dependencies):
  a11y, auth, bitrix-sdk, commerce, i18n, observability, perf, seed-data, seo

Wave 1 (depend on Wave 0):
  tenant-resolver → seed-data
  ui → i18n

Wave 2 (depend on Wave 0 + Wave 1):
  testing → i18n, tenant-resolver, ui
```

## Publish Order (topological)

Packages must be published in dependency order so that consumers can
resolve their dependencies from the registry.

### Wave 0 — Leaves (9 packages, parallelisable)

1. `@journeyoflife-org/a11y`
2. `@journeyoflife-org/auth`
3. `@journeyoflife-org/bitrix-sdk`
4. `@journeyoflife-org/commerce`
5. `@journeyoflife-org/i18n`
6. `@journeyoflife-org/observability`
7. `@journeyoflife-org/perf`
8. `@journeyoflife-org/seed-data`
9. `@journeyoflife-org/seo`

### Wave 1 — First-level dependents (2 packages, parallelisable)

10. `@journeyoflife-org/tenant-resolver` (depends on `seed-data`)
11. `@journeyoflife-org/ui` (depends on `i18n`)

### Wave 2 — Second-level dependents (1 package)

12. `@journeyoflife-org/testing` (depends on `i18n`, `tenant-resolver`, `ui`)

## Per-Package Work Required

For each package, the following changes are needed:

1. **Remove `"private": true`** (or set to `false`).
2. **Add `"build": "tsup"` script.**
3. **Add `tsup.config.ts`** — emit ESM + CJS + `.d.ts` to `dist/`.
4. **Rewrite `exports`** — every subpath needs `types` + `import` +
   `require` conditions pointing into `dist/`.
5. **Add `"files": ["dist"]`** — only publish the build output.
6. **Add `"publishConfig"`** — registry URL + `"access": "restricted"`.
7. **Add `"sideEffects"`** — critical for `ui` (CSS files must be listed
   or Tailwind styles will be tree-shaken away).
8. **Resolve `workspace:*` dependencies** — at publish time, pnpm
   rewrites these to version ranges automatically.

## Special Cases

### `@journeyoflife-org/ui` — The Hard One

- 12 export subpaths (not 17 — the dangling donation export was removed)
- Includes a wildcard export: `"./components/*": "./src/components/*/index.ts"`
- Two CSS files: `./styles/globals.css`, `./styles/tokens.css`
- Tailwind config: `./tailwind`
- **The wildcard cannot survive a build.** Must enumerate component
  directories explicitly. Generate the list by script so it cannot drift.

### `@journeyoflife-org/i18n` — Many Subpaths

- 13 export subpaths (likely one per locale + barrel)
- Need to verify all resolve after build

### `@journeyoflife-org/testing` — Dev-Only?

- Depends on `ui`, `tenant-resolver`, `i18n`
- May not need to be published if it's only used in hub CI
- Decision: publish it (spokes may want integration test utilities)

## Registry Decision (Deferred to Task 2.4)

Two options, both work:

1. **Verdaccio on-prem** — self-hosted, EU-jurisdiction, no GitHub
   dependency. Requires a Proxmox CT + nginx reverse proxy + auth.
2. **GitHub Packages** — managed, no infra, but requires GitHub auth
   for install (spokes need a PAT or GitHub Actions token).

Recommendation: **GitHub Packages** for pilot speed; Verdaccio for
production if EU-jurisdiction becomes a hard requirement.

## Rollback

Reverting this plan means re-adding `"private": true` to all packages
and removing the build step. No spoke should depend on published packages
until Phase 3 (spoke scaffolding), so rollback before then loses nothing.

## Success Criteria

- `pnpm publish --dry-run` exits 0 for all 12 packages in publish order.
- Each package's `dist/` contains ESM, CJS, and `.d.ts` files.
- All `exports` subpaths resolve to files in `dist/`.
- The wildcard export in `ui` is replaced with an explicit enumerated
  list (generated by script).
- `sideEffects` is correct for `ui` (CSS files listed).
